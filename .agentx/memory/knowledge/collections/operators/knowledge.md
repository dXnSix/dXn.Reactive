# Collection Operators Knowledge

- Live cache grouping keeps a stable outer group collection and publishes member changes only to groups addressed by the source batch. The focused sparse-batch contract covers same-group middle updates and one cross-group update; its fixed input benchmark sizes are 640, 1280, and 10000.
- `CacheSortState` keeps indexed source and sorted-key positions for ordinary keyed updates. Large initial add-only batches (64 or more entries) populate source state once, then use one stable sort and indexed `Add` output instead of repeated linear sorted insertion. The keyed-sort benchmark records fixed U=640, 1,280, and 10,000 populations.
- `ChangeStream` owns common DynamicData-style stream controls: `start_with_empty`, `not_empty`, `monitor_status`, `defer_until_loaded`, `skip_initial`, `buffer_initial`, recurring timed `batch`, `batch_count`, `batch_if`, `buffer_if`, `batch_if_with_timeout`, and `buffer_if_with_timeout`. `monitor_status` emits `Pending` then `Loaded` under the current non-terminal stream contract, `skip_initial` follows DynamicData's `defer_until_loaded().skip(1)` behavior by dropping the first non-empty loaded batch, `buffer_initial` coalesces the first timed burst into one `ChangeSet`, `batch_if` / `buffer_if` buffer source changes while a `ValueStream<bool>` pause signal is true and flush one `ChangeSet` when the pause signal becomes false, and timeout variants auto-resume and flush the active paused buffer if the timeout elapses first.
- `ListStreamExt` and `CacheStreamExt` expose DynamicData-style `where_reasons_are`, `where_reasons_are_not`, and `suppress_refresh` operators; they filter individual changes and suppress batches that become empty.
- Cache duplicate-key reduction is exposed as `CacheStreamExt::ensure_unique_keys()`. It mirrors DynamicData's `UniquenessEnforcer`: moved changes are ignored, repeated same-key changes choose the last non-refresh change unless all are refreshes, and add-then-remove can emit an intentionally empty `ChangeSet`.
- Dynamic filters are exposed as `filter_dynamic(ValueStream<Predicate<T>>)` and `filter_with_state(ValueStream<S>, predicate)`. No source items pass until the predicate/state stream emits its first value; source changes after a state is available are handled incrementally by translating source order into visible indexes for lists and caches, while later state emissions re-query all tracked items and emit structured diff changes. These operator signatures accept `rayx_reactive::primitives::ValueStream<_, E>` when `CollectionError: From<E>`, so `rayx_reactive::Signal::values()` streams with `ReactiveError` can be passed directly.
- `ListStreamExt::filter` is an incremental DynamicData static list filter. It stores each upstream item's inclusion state, computes downstream indexes by counting included items before the source index, preserves add/range/replace/move/remove/range/refresh/clear reasons where possible, and suppresses empty filtered batches.
- Cache filtering re-evaluates on `Refresh`, so mutable external predicate state can promote a previously excluded item to `Add`, demote an included item to `Remove`, or forward `Refresh` when the item remains included.
- `CacheStreamExt::filter_immutable` and `filter_immutable_with_options` are stateless DynamicData `FilterImmutable` equivalents for immutable items and deterministic predicates. They do not keep an included-item cache, strip output indexes to `None`, drop move changes, convert updates into add/remove/update based only on previous/current predicate results, and suppress empty changesets by default. The current DynamicData source propagates matching refresh changes despite some public remarks saying refresh is dropped, so the crate follows DynamicData source behavior.
- `CacheTypeFilterExt::of_type` is the Rust type-erased cache equivalent for DynamicData `OfType`. Source streams use `Arc<dyn Any + Send + Sync>` values and downcast to `Arc<U>` without cloning inner values; add/update/remove/refresh/clear payloads are filtered by runtime type, move changes are dropped, output indexes are stripped, and empty batches are suppressed by default.
- `ListAggregationExt` and `CacheAggregationExt` expose DynamicData-style `query_when_changed`, `to_collection`, `to_sorted_collection`, `to_sorted_collection_by`, `count`, `is_empty`, `is_not_empty`, `sum_by`, `avg_by`, `std_dev_by`, `min_by`, and `max_by` streams. These operators maintain incremental list/cache numeric state where practical, emit derived values after non-empty change sets, suppress empty batches so upstream duplicate-key reduction does not create redundant aggregate notifications, and suppress unchanged min/max values to match DynamicData's `DistinctUntilChanged` extrema behavior. Cache aggregation also exposes `query_when_changed_on` / `query_when_changed_on_with`, which keep a cache snapshot and emit a fresh query when a per-item `ValueStream` fires without synthesizing source refresh changes.
- `ListDiagnosticsExt::collect_update_stats` and `CacheDiagnosticsExt::collect_update_stats` emit DynamicData-style `ChangeSummary` values containing the latest batch counts and overall accumulated `ChangeStatistics`. List add/remove ranges count item payload lengths while `count` remains the number of change records; cache `Clear` counts removed payload items from `previous` while `count` remains one change record.
- `ListCombineExt` and `CacheCombineExt` expose static DynamicData-style logical combiners: `or`, `and`, `xor`, and `except`. `DynamicListCombineExt` and `DynamicCacheCombineExt` expose source-list-driven dynamic combiners for child changeset streams. They keep independent source state, recompute only keys/items touched by incoming changes or source-list structure, preserve deterministic source/list order, and emit structured result changes rather than reset snapshots.
- `CacheLimitExt::limit_size_to(size)` keeps the `size` most recently added or updated keys and emits per change (forwarding refreshes and same-value updates of held keys). Items pruned by the limit do not reappear after unrelated upstream removals; an upstream add/update for the same key makes it active again as the newest.
- `CacheJoinExt` exposes same-key `inner_join`, `left_join`, `right_join`, and `full_join` operators plus grouped `inner_join_many`, `left_join_many`, `right_join_many`, and `full_join_many`. Join-many keeps live `RayCacheGroup` values for right-side groups, re-runs selectors only for affected left/group keys when right membership changes, and supports left-only, right-only, inner, and full grouped results without snapshot resets.
- `ListDistinctExt::distinct_values` and `CacheDistinctExt::distinct_values` maintain reference counts for selected values and emit `ListChange` updates only when a value's live count crosses between zero and nonzero. Cache distinct values also track each source key's currently selected value so updates and refreshes can adjust counts without rescanning the cache.
- `ListLifecycleExt` and `CacheLifecycleExt` expose DynamicData-style `on_item_added`, `on_item_removed`, `on_item_removed_with_unsubscribe`, `on_item_refreshed`, `subscribe_many`, and cache `on_item_updated`. List replacements invoke added callbacks for the new item and removed callbacks for the old item; cache updates use the separate updated callback. `subscribe_many` creates per-item subscriptions on add/replace/update, leaves refreshes alone, and disposes active subscriptions on remove, clear, replacement/update, or stream disposal.
- `ListLifecycleExt::dispose_many*` and `CacheLifecycleExt::dispose_many*` are Rust-native DynamicData `DisposeMany` equivalents. `DisposeItem` supports no-argument disposal for user types, while `dispose_many_with` accepts explicit finalizer closures; cache also exposes `dispose_many_by` so callers can decide whether an update's previous/current values represent the same resource. The operator forwards each source `ChangeSet` first, then finalizes removed/replaced values, and finalizes remaining tracked values when the downstream subscription is disposed.
- `CacheLifecycleExt::async_dispose_many*` mirrors DynamicData cache `AsyncDisposeMany` for Rust futures. `AsyncDisposeItem` supports consuming async finalizers, while `async_dispose_many_with` and `async_dispose_many_by` accept explicit future-returning finalizers and optional same-resource equality. Each downstream subscription owns one worker thread and future queue, forwards source `ChangeSet`s before enqueueing removed/replaced finalizers, drains remaining tracked values on subscription disposal, and exposes a per-subscription completion `ValueStream<()>` through the caller accessor.
- `CacheLifecycleExt::invoke_evaluate*` mirrors DynamicData `InvokeEvaluate` for refresh-aware cache items. `EvaluateItem` supports no-argument evaluation for user types and `invoke_evaluate_with` accepts an explicit evaluator closure. Only `Refresh` changes trigger evaluation, and evaluation runs before forwarding the unchanged batch downstream.
- `ListLifecycleExt::auto_refresh` and `CacheLifecycleExt::auto_refresh` subscribe to a `ValueStream` per live item and inject structured `Refresh` changes when the item signal fires. List refreshes preserve current indices across moves by tracking stable internal item ids; cache refreshes use the live key and current item, recreate item signal subscriptions on add/update, and dispose them on remove/clear.
- `ListLifecycleExt::auto_refresh_buffered` and `CacheLifecycleExt::auto_refresh_buffered` mirror DynamicData's AutoRefresh change-set buffering: ordinary source batches are forwarded immediately, while child refresh triggers are coalesced for the requested duration and materialized against the current list index/cache order at flush time. Repeated triggers for the same live list id or cache key inside one buffer window emit one refresh.
- `ListLifecycleExt::merge_many` and `CacheLifecycleExt::merge_many` are flat `ValueStream` operators, matching DynamicData's non-changeset `MergeMany`: they subscribe to one child value stream per live item, merge child values into one output stream, recreate child subscriptions on list replace/cache update, and dispose child subscriptions on remove/clear/source disposal.
- `CacheLifecycleExt::merge_many_items` and `merge_many_keyed_items` mirror DynamicData's cache `MergeManyItems` pattern for Rust streams. They attach the source item, or key plus source item, to each child emission as `ItemValue<T, U>` / `KeyedItemValue<K, T, U>` while reusing the same per-item subscription lifetime as flat `merge_many`.
- `ListLifecycleExt` and `CacheLifecycleExt` expose Rust-native DynamicData `WhenValueChanged` equivalents over per-item `ValueStream` selectors. `when_value_changed` forwards flat child values, `when_value_changed_with_initial` prepends a caller-selected current value for each live item, `when_item_value_changed*` emits `ItemValue<T, U>` owner/value payloads, and cache `when_keyed_value_changed*` emits `KeyedItemValue<K, T, U>` payloads. These methods reuse the merge-many/merge-many-items paths, so update/replacement/removal cleanup and stale child suppression stay aligned with flat per-item stream merging.
- `ListLifecycleExt::filter_on_observable` and `CacheLifecycleExt::filter_on_observable` subscribe to a per-item `ValueStream<bool>` and emit touched add/remove/refresh/move changes as each boolean changes. The crate uses the predictable cache-style rule for both lists and caches: items are excluded until their own stream emits `true`; list replacement and cache update reset inclusion and require a new `true` from the replacement stream.
- `CacheLifecycleExt::transform_on_observable` starts one child `ValueStream` per live key, suppresses output until the child first emits, emits `Add` for the first child value and `Update` for later distinct values, forwards source `Refresh` only after the key is visible, replaces child subscriptions on source update while keeping the previous transformed value until the replacement emits, disposes child subscriptions on remove/clear/source disposal, and coalesces synchronous child startup emissions into one `ChangeSet`.
- `ListStreamExt::transform_many` flattens parent items into an ordered child list. It tracks one child vector per parent, preserves parent/source order and child order, emits range adds/removes for parent range changes, diffs child collections on parent replace/refresh, and maps parent moves to child remove/add ranges only when the flattened order changes.
- `CacheStreamExt::transform_many` flattens keyed parent items into keyed child cache changes. Parent updates/moves diff prior and current child maps by child key; parent refreshes reconcile mutable child maps by emitting child remove/add/update changes and forwarding `Refresh` for unchanged child keys.
- `CacheStreamExt::transform_many_async*` expands keyed parent cache items through future-returning child factories. The iterable overload wraps each completed child collection as a one-shot child cache stream; the stream overload subscribes to a live child `ChangeStream`. The operator keeps per-parent generations, stable per-parent child key order, a merged result cache, and optional comparer-based duplicate child-key selection so stale async completions and disposed child streams cannot publish after parent replacement/removal.
- `CacheStreamExt::transform_many_safe_async*` reports failed async parent materialization through `TransformError` and substitutes an empty child stream. Parent replacement still uses the existing transform-many generation state, so old children are removed/disposed and stale later child emissions remain suppressed.
- `CacheStreamExt::group`, `group_with_key`, `group_with_regrouper`, `group_with_key_and_regrouper`, `group_dynamic`, and `group_dynamic_with_regrouper` expose DynamicData-style live cache grouping. The outer stream emits `RayCacheGroup` add/remove changes only when group existence changes, member add/update/remove/refresh/move changes are published through each group's read-only keyed cache stream, refresh/regrouper/dynamic selector changes can move items between groups, dynamic grouping buffers source items until the first `GroupSelector` arrives, and groups emptied then refilled in the same source batch keep stable identity.
- `CacheLifecycleExt::group_on_observable` emits live `RayCacheGroup` values keyed by group key. Each source key is invisible until its child group-key stream emits, duplicate child group keys are suppressed, source update/remove/clear disposes the old child subscription and removes the item from its current group, empty groups are removed after each source/child turn, groups refilled in the same turn keep stable identity, and each group exposes a read-only keyed cache stream through `connect`, `items`, `keys`, `key_values`, `lookup`, and `count`.
- `ListStreamExt::group` and `group_with_regrouper` expose DynamicData-style live list grouping. The outer stream emits `RayListGroup` add/remove changes only when group existence changes; each group exposes a read-only live list through `connect`, `items`, `len`, `count`, and `is_empty`; source replace/refresh/regrouper changes can move items between groups; pure source moves update inner group member order without outer group churn; and groups emptied then refilled in the same source batch keep stable identity.
- `ListStreamExt::group_immutable*` and `CacheStreamExt::group_immutable*` expose DynamicData `GroupWithImmutableState`-style snapshot grouping. They maintain source order plus group membership internally, emit immutable `ImmutableListGroup` / `ImmutableCacheGroup` snapshots for touched groups, preserve group creation order until a group is empty after the whole batch, treat groups emptied and refilled in the same batch as snapshot replacements, and support regrouper streams for mutable group selectors without creating live child group subjects.
- `CacheExpireAfterExt` and `ListExpireAfterExt` expose stream-level `expire_after` / `expire_after_with_polling` (+ `*_with_scheduler`) operators that forward source changes translated to their own output and emit timer-driven remove changes for expired items. One scheduler timer per subscription fires at the next due time (or every polling interval while items wait); add/update (cache) and add/replace (list) reset the time to live, refreshes and moves do not; disposal cancels the timer.
- `SourceCacheExpireAfterExt` and `SourceListExpireAfterExt` expose source-mutating `expire_after` / `expire_after_with_polling` (+ `*_with_scheduler`) operators. Due items are taken and removed inside one source edit (`edit_at_version`, only from a mirror that has seen every committed batch), and the value stream emits the pairs or items that edit removed.
- `CacheStreamExt::ignore_update_when`, `include_update_when`, and `ignore_same_value_update` mirror DynamicData's lazy update filtering by evaluating only `Update` changes and forwarding add/remove/refresh/move/clear changes unchanged; batches that become empty are suppressed. `CacheArcStreamExt::ignore_same_reference_update` is the Rust reference-identity equivalent for `Arc<T>` payloads and uses `Arc::ptr_eq`.
- `CacheStreamExt::transform` now follows DynamicData's default cache transform semantics: add/update call the transform factory, remove/clear remove projected items, move forwards the existing projected value, and refresh forwards a `Refresh` containing the existing projected value without re-running the transform. `transform_on_refresh` and `transform_with_previous_on_refresh` opt into retransforming refreshes and emit keyed updates.
- `CacheStreamExt::transform_safe*` and `transform_safe_async*` are Rust `Result`-returning equivalents of DynamicData `TransformSafe` / `TransformSafeAsync`. Failed per-item projections call the provided `TransformError { key, value, error }` handler, keep the source mirror and key order current, leave the previous projected value unchanged, suppress empty output batches, and let a later source update or forced retransform emit `Add` when a previously failed key succeeds.
- `CacheStreamExt::transform_immutable` mirrors DynamicData `TransformImmutable`: it maps each incoming cache change directly through a pure transform function without maintaining a projected cache. Add/update/remove/refresh/move/clear payloads are transformed from the current or previous source payload carried by the change, and input indexes are preserved.
- `ListStreamExt::transform` is an incremental DynamicData-style list transformer, not a snapshot recompute. It keeps the projected list state, forwards add/range/replace/move/remove/range/clear as matching indexed list changes, forwards refresh with the existing projection by default, and exposes `transform_with_previous`, `transform_on_refresh`, and `transform_with_previous_on_refresh` for factories that need the previous projection or explicit refresh re-transformation.
- `CacheStreamExt::transform_with_forced`, `transform_with_previous_forced`, and `transform_with_forced_all` keep source and projected caches internally. Forced predicate emissions re-transform only matching live keys and emit updates against the previous projection; operator output versions stay monotonic across source and forced batches.
- `CacheStreamExt::transform_inline` and `transform_inline_on_refresh` create one projected value on add, mutate the existing projected value on source updates, and emit `Refresh` so object identity can be preserved for view-model-style projections.
- `ListStreamExt::transform_async*` and `CacheStreamExt::transform_async*` are worker-backed Future-returning transforms. Source callbacks enqueue batches and return quickly; list async transforms process source batches in order and preserve indexed list semantics, while cache async transforms can run per-key jobs with `TransformAsyncOptions::maximum_concurrency`, emit one output changeset after the batch completes, forward refreshes by default, and re-transform refreshes or forced predicates only when the caller opts in.
- `ListStreamExt::treat_moves_as_remove_add` and `CacheStreamExt::treat_moves_as_remove_add` rewrite move changes into remove/add pairs while preserving the original item/key and previous/current indices. This is useful before binding targets that do not support stable move notifications.
- `ListStreamExt::reverse` mirrors DynamicData's lazy reverser: it tracks source length and rewrites each incoming add/range/remove/range/move/replace/refresh/clear index into the reversed coordinate space without recomputing the whole list.
- `ListSwitchExt`, `CacheSwitchExt`, `SourceListSwitchExt`, and `SourceCacheSwitchExt` expose DynamicData-style `Switch`. Each new inner stream/source clears the previous visible state, disposes the previous inner subscription, subscribes to the latest stream, and ignores stale notifications from older generations.
- `ListRefCountExt::ref_count` and `CacheRefCountExt::ref_count` materialize a shared list/cache state on the first downstream subscriber, replay a structured snapshot to late subscribers, keep one upstream subscription while any downstream subscriber is alive, and drop the upstream subscription plus materialized state when the last subscriber leaves.
- `CacheTrueForExt` and `SourceCacheTrueForExt` expose DynamicData-style `true_for_all` / `true_for_any` streams over per-item `ValueStream`s. Items whose child stream has not emitted count as false, empty all is true, empty any is false, duplicate boolean results are suppressed, source updates replace child subscriptions, and removed children cannot publish stale values.
- `ListStreamExt::top(n)` is implemented as the fixed zero-based virtual window DynamicData documents; `n == 0` panics with a clear invalid-size message. `CacheStreamExt::start_with_item(key, item)` prepends a one-item add changeset event and then forwards source changes without pinning the seeded item in later ordered bindings.
- `SourceCacheLimitExt::limit_size_to(size)` mutates a `SourceCache` directly, removes oldest keys when live count exceeds the limit (picked inside the edit from a version-checked mirror), treats add/update as recency touches, and emits evicted key-value batches.
- `SourceListLimitExt::limit_size_to(size)` mutates a `SourceList` directly, tracks stable per-entry ids and write sequences so duplicate values and moves remain correct, treats replace/add as newest entries, preserves refresh/move sequence, removes the oldest indices in descending order inside the edit, and emits evicted items.
- `CacheStreamExt::change_key` and `change_key_with_source_key` mirror DynamicData's `ChangeKey`: they preserve the incoming change reason and payload, recompute the destination key from the current item for add/update/refresh/move, from the removed item for remove, and from each removed item for clear. They intentionally do not synthesize remove/add pairs when an update maps to a different destination key.
- `ListStreamExt::add_key` converts list changes into keyed cache changes using a caller key selector. Add/add-range become keyed adds, same-key replace becomes update, key-changing replace becomes remove plus add, move preserves previous/current indices, remove/remove-range/clear become keyed removes, and refresh becomes keyed refresh.
- `CacheStreamExt::remove_key` converts keyed cache changes into applyable list changes using an ordered key mirror because `ListChange` requires concrete indices. Cache update maps to list remove plus add, refresh uses tracked index when upstream lacks one, and clear emits list clear for full clears or descending removes for partial key clears.
- `CacheTreeExt::transform_to_tree` builds DynamicData-style hierarchical views from flat keyed cache streams. `TreeNode` owns a live `SourceCache` of children, exposes `key`, `item`, `parent`, `parent_key`, `is_root`, and `depth`, defaults the visible output to root nodes, attaches late-arriving parents to existing children, promotes direct children to roots when a parent is removed, re-parents on update/refresh when the pivot key changes, and supports `transform_to_tree_with_predicate(ValueStream<TreePredicate<_, _>>)` for dynamic node filtering.
- `OptionValueExt`, `OptionValueStreamExt`, `OptionIteratorExt`, and `IterableCollectionExt` provide Rust-native DynamicData kernel helpers over `Option<T>`, `ValueStream<Option<T>>`, and iterators: convert/and-then optional values, fallback values, side-effect hooks, value-only selection, `Result` emission for missing optional values, duplicate detection, first optional match, and indexed lookup/multi-lookup through `ItemWithIndex<T>`.
- `ListSideEffectExt` and `CacheSideEffectExt` expose DynamicData-style forwarding utility operators: `for_each_batch`, `for_each_change`, list `for_each_item_change`, list `flatten_item_changes`, cache `flatten_changes`, and Rust-specific `clone_into_vec`. `ListItemChange` flattens list range changes into per-item add/remove entries while preserving replace/move/refresh item metadata.
- `ListItemChange::without_indexes` / `to_without_indexes` and `ListSideEffectExt::flatten_item_changes_without_indexes` are the Rust equivalent of DynamicData list `RemoveIndex` / `YieldWithoutIndex` behavior. They strip index metadata from flattened item changes without weakening the primary `ListChange` type, which continues to require concrete indexes for applyable list changes.
- `ListBufferExt::flatten_buffer_result` and `CacheBufferExt::flatten_buffer_result` convert `ValueStream<Vec<ChangeSet<_>>>` buffers back into single changeset streams by concatenating non-empty buffered changes and using the last buffered version.
- Dynamic list paging/windowing is exposed as `page_dynamic` and `virtualize_dynamic` over `ValueStream<PageRequest>` / `ValueStream<VirtualRequest>`. Request streams are subscribed before the source so synchronous initial requests shape the initial source snapshot; static `page`/`virtualize` preserve the Rust zero-based request contract.
- List page/window response metadata is exposed through `page_with_response`, `page_dynamic_with_response`, `virtualize_with_response`, and `virtualize_dynamic_with_response`. These return `ValueStream<PageChangeSet<T>>` / `ValueStream<VirtualChangeSet<T>>` values that carry the inner list `ChangeSet` plus visible count, requested page/start, total count, and total pages for page streams.
- `PageRequest::default()` is `PageRequest::new(0, 25)`, `PageRequest::EMPTY` is `PageRequest::new(0, 0)`, and `VirtualRequest::default()` is `VirtualRequest::new(0, 25)`. This intentionally follows the crate's zero-based page/window contract rather than DynamicData's one-based default page number.
- `ListStreamExt` and `CacheStreamExt` expose dynamic sorting via list-shaped `sort_by`, `sort_by_key`, `sort_by_key_descending`, `sort_dynamic`, `sort_with_resort`, and `sort_dynamic_with_resort`. `CacheStreamExt` also exposes keyed sorted cache streams through `sort_keyed_by`, `sort_keyed_by_key`, `sort_keyed_by_key_descending`, `sort_keyed_dynamic`, `sort_keyed_with_resort`, and `sort_keyed_dynamic_with_resort`. Projection-key sorting builds ascending/descending comparers over the existing incremental sorter, mirroring DynamicData `SortBy` / `SortExpressionComparer` selector semantics. Ordinary source changes mutate the sorted target incrementally: list sort inserts/removes/replaces/moves sorted values directly, list-shaped cache sort emits list changes, and keyed cache sort emits indexed `CacheChange` adds/updates/removes/refreshes/moves so downstream cache materializers retain keys and sorted coordinates. Comparer streams and explicit resort streams re-sort the tracked source state.
- `CacheStreamExt::update_index` is the Rust equivalent of DynamicData `UpdateIndex` for sorted keyed cache streams. `IndexAware::set_index` is object-safe and has a blanket `Arc<T>` implementation, while `update_index_with` accepts a closure for non-trait or interior-mutable item designs. The operator maintains the current keyed order from incoming indexed cache changes, updates every live item index before forwarding each batch, and expects shared/interior-mutable items when callers want side effects to be visible outside the operator's cloned state.
- `CacheStreamExt::page_keyed*`, `top_keyed`, and `virtualize_keyed*` window any ordered keyed cache stream, including `sort_keyed_by` output, while preserving keys and emitting indexed `CacheChange` diffs plus `KeyedPageChangeSet` / `KeyedVirtualChangeSet` response metadata. These operators maintain ordered keyed snapshots and reuse `diff_cache_snapshots`, so page/window changes stay aligned with cache materialization semantics.
- `CacheStreamExt` exposes DynamicData-style direct sorted cache windowing through `sort_and_page_*` and `sort_and_virtualize_*` methods. These operators keep source cache state, source order, sorted key/value entries, and the visible page/window in one state machine instead of composing through a full sorted list stream; requests and comparers are dynamic, equal comparer results preserve source order, response metadata uses the crate's zero-based `PageRequest` / `VirtualRequest` contract, and visible `Update` / `Refresh` changes can emit list refreshes when the visible item remains in place.
- `ListLifecycleExt::merge_many_list_change_sets` and `CacheLifecycleExt::merge_many_list_change_sets` merge child list change-set streams from live parent items. They subscribe to child lists on parent add/update/replace, remove previously published child items on parent remove/clear/replacement, and dispose child subscriptions so removed parents cannot publish later child changes.
- `ListLifecycleExt::merge_many_cache_change_sets` and `CacheLifecycleExt::merge_many_cache_change_sets` merge child cache change-set streams from live parent items. The result keeps one item per child key, uses first live parent/source order as the default duplicate-key winner, supports `merge_many_cache_change_sets_by` comparer overloads for best-value selection, recomputes fallback winners on child/parent update or removal, preserves ordered touched-key recomputation for stable `bind_to_vec` indices, and disposes removed parent child subscriptions.
- Static `merge_list_change_sets`, `merge_cache_change_sets`, and `merge_cache_change_sets_by` wrap child streams in an internal `SourceList` and reuse the `merge_many_*_change_sets` machinery, so static merge semantics stay aligned with parent/child dynamic merge behavior instead of maintaining a separate aggregator.
