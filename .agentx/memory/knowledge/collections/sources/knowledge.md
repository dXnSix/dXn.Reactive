# Collection Sources Knowledge

- `SourceList` exposes direct mutation helpers over the same single-edit batching path as `edit`: `push`, `add_range`, `insert`, `insert_range`, `replace`, `replace_item`, `move_item`, `remove`, `remove_item`, `remove_many`, `remove_range`, `refresh`, `refresh_all`, `clear`, `load`, `edit_diff`, and `edit_diff_by`. `load` clears then appends the supplied snapshot in one edit, while `edit_diff` / `edit_diff_by` reuse the shared minimal list diff helper and emit one structured batch.
- `SourceCache` exposes direct mutation helpers over `edit`: `add_or_update`, `add_or_update_range`, `remove_key`, `remove_item`, `remove_keys`, `remove_items`, `refresh_key`, `refresh_item`, `refresh_items`, `refresh`, `move_key`, `clear`, `load`, `edit_diff`, and `edit_diff_by`. Cache `load` clears then adds the supplied snapshot in one edit; cache `edit_diff` / `edit_diff_by` remove missing keys, update changed values, add new keys, and move existing equal values into the requested order.
- `SourceCache` and `CacheUpdater` expose equality-aware upserts via `add_or_update_if_changed`, `add_or_update_by`, `add_or_update_range_if_changed`, and `add_or_update_range_by`. These mirror DynamicData's comparer overloads by skipping existing-key updates when the previous and current item compare equal, leaving the cache value and downstream streams untouched.
- `CacheStreamExt::watch(key)` filters any generic cache changeset stream to one key. Direct `SourceCache::watch(key)` instead registers with one source-owned `KeyedChangeHub`: its startup snapshot clones only the requested entry, the hub partitions each published batch once, and only subscribers for touched keys are invoked. The versioned startup buffer is connection-local and no source history is scanned or retained. `CacheStreamExt::watch_value(key)` / `SourceCache::watch_value(key)` emit values for that key; `watch_value` follows DynamicData's behavior of emitting the removed value on remove/clear instead of an optional absence marker.
- `SourceCache`, `SourceList`, `RayCacheGroup`, and `RayListGroup` close snapshot/live races with `StartupConnection`, not replay storage. It subscribes before snapshot, discards buffered versions covered by the snapshot, drains newer versions in order, and releases its temporary buffer on disposal.
- The shared list snapshot diff uses per-index `Replace` for equal-length changes and a bounded localized middle diff otherwise. It reserves `Clear` for an empty target and emits structured remove/add ranges when the middle work budget is exceeded.
- `CacheStreamExt::watch_optional(key)` and `SourceCache::watch_optional(key)` emit `Option<T>` for keyed presence, suppressing duplicate `Some` values with `PartialEq` and emitting `None` on remove/clear. `SourceCache::watch_optional_with_initial(key, true)`, `CacheStreamExt::watch_optional_with_initial(key, true)`, and `ObservableCache::watch_optional_with_initial(key, true)` emit an initial `None` only when the key is not observed synchronously during subscription.
- `ListPopulateExt::populate_into` and `CachePopulateExt::populate_into` subscribe to a changeset stream and apply each batch into a destination `SourceList`/`SourceCache` in one destination edit. Cache population uses `CacheUpdater::add_or_update_at` so incoming current indices are preserved instead of degrading ordered cache streams into append-only updates.
- Cache population applies incoming `CacheChange` keys through `CacheUpdater::add_or_update_key_at`; remapped-key streams therefore materialize under the stream key even when the item has a different natural `SourceCache` key selector.
- `ObservableList` and `ObservableCache` are read-only query/connect wrappers over sources or materialized change streams. Stream materialization keeps the populate subscription alive inside the wrapper, exposes query/count/connect/changes/preview APIs, and lets multiple downstream `connect` subscribers share one materialized pipeline.
- Cache streams now expose `CacheStreamObservableListExt::as_observable_list()`, which removes keys through the ordered cache-to-list bridge before list materialization. This lets sorted keyed streams such as `source.connect().sort_keyed_by_key(...).as_observable_list()?` become ordered read-only list views for ViewModels and virtualized controls without exposing the mutable `SourceCache`.
- `SourceListPopulateFromExt` and `SourceCachePopulateFromExt` subscribe to item or batch `ValueStream`s and mutate the target source in one source edit per emission: list items append, list batches add ranges, cache items add-or-update, and cache batches add-or-update ranges.
- `ValueStreamListDiffExt::edit_diff_list` / `edit_diff_list_by` convert `ValueStream<Vec<T>>` complete snapshots into structured list changes by reusing the same list diff helper as list operators. They suppress unchanged snapshots, emit range adds for initial snapshots, targeted add/remove/replace changes when possible, and clear/add-range fallback changes for broad rewrites.
- `ValueStreamCacheDiffExt::edit_diff` / `edit_diff_by` convert `ValueStream<Vec<T>>` complete snapshots into keyed cache changes, emitting add/update/remove and move changes against the previous materialized snapshot. `OptionalValueStreamCacheDiffExt::edit_diff_optional` / `edit_diff_optional_by` convert `ValueStream<Option<T>>` into single-item add/update/remove changes, including remove/add when the selected key changes.
- `ValueStreamListChangeSetExt`, `ValueStreamListBatchChangeSetExt`, `ValueStreamCacheChangeSetExt`, and `ValueStreamCacheBatchChangeSetExt` convert progressive item/batch `ValueStream`s into changeset streams by creating a private source per downstream subscription. Downstream output is subscribed before upstream input so synchronous upstream value emissions are not lost.
- Value-stream-to-changeset adapters accept `ChangeSetAdapterOptions<T>` for DynamicData-style `ToObservableChangeSet` limit and expiration behavior. The options activate source-owned FIFO size limiting and per-item expiration against each adapter's private backing source, so stream callers can bound append/upsert feeds without exposing or mutating an external source.
- `create_list_change_stream` and `create_cache_change_stream` are the Rust equivalents of DynamicData `ObservableChangeSet.Create`: each downstream subscription gets a private `SourceList`/`SourceCache`, the private source `connect()` output is subscribed before the caller driver runs, and the returned `Subscription` keeps both the driver and backing source alive for the downstream subscription lifetime.
- Cache list materialization honors sorted keyed `Update` changes by removing the previous indexed slot and inserting the current value at `current_index` when `previous_index` and `current_index` differ; treating all cache updates as in-place replacements leaves stale rows in sorted bound views.
